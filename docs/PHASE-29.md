# Phase 29: MACRO listings, traceback, and debugger records

## Goal

Give govax's `MACRO` command the outputs real MACRO has that Phase 27 left
out:

- **Listing files** (`/LIST`): the source beside the generated bytes, the
  symbol table, the psect synopsis, and the run statistics, laid out as
  real MACRO lays them out.
- **Traceback records** (TBT), which real MACRO writes by default
  (`.ENABLE TRACEBACK`), so that a failing image gives a symbolic
  traceback, and LINK's debug symbol table (DST) built from them.
- **Debugger records** (DBG, for `/DEBUG` and `.ENABLE DEBUG`).

The author answered both on 2026-10-02.

1. **Listing fidelity.** A listing doesn't need perfect fidelity, but

## What a real listing looks like

From the 30 real listings already in `testdata/` (`mar/vax`,
`mar/macros/vax`, `link/vax`). The probe (subtask 1) settles what they
don't show.

- **Pages.** Each page starts with a form feed and is 60 lines long,
  heading included; lines are at most 132 characters.
- **Heading, line 1:** the module name (`.TITLE`'s, padded to 32
  columns), the `.TITLE` text cut to 40 characters, the assembly date
  and time, the assembler's name and version (`VAX MACRO V5.4-3`), and
  `Page n`.
- **Heading, line 2:** the `.IDENT` string (or, on the closing pages,
  `Symbol table` and `VAX-11 Macro Run Statistics`), the source file's
  revision date and time, its full file specification, and its file
  number in parentheses (`(1)`). Then a blank line.
- **Source lines:** a binary field right-aligned to column 37, a 4-digit
  location, a 5-digit line number, a space, and the source line as
  written, tabs kept. A `.PSECT` line shows the psect's 8-digit location
  where the binary field ends; a direct assignment or `.BLKx` shows the
  8-digit value there. An instruction's bytes read right to left, the
  opcode rightmost, each operand specifier its own group; a relocatable
  field ends in `'`, and a general-mode (`G^`) specifier, whose mode the
  linker picks, shows `GF`. Data too long for one line continues on
  lines with only the binary field and the location.
- **Macro calls and repeat blocks**, under the defaults: a macro call
  shows its line and none of its expansion, with no bytes; a repeat
  block's lines are listed once, and its first bytes appear on the
  `.ENDR` line (`usermac.lis`). `.PRINT`'s message follows its line.
- **Symbol table** (a new page): every symbol in name order, name column
  as wide as the longest name, then `=` for an assigned symbol, the
  8-digit value (`********` if undefined), and `R` (relocatable), `G`
  (global), `X` (external), and the psect number. Local labels aren't
  listed. Not every defined symbol is listed (`rmscopy.lis` lists about
  55 of its 625), which the probe has to explain.
- **Psect synopsis:** a boxed heading, then each psect's name, size in
  hex and decimal, number in hex and decimal, and its attributes in
  fixed columns, `.  ABS  .` first.
- **Performance indicators:** a boxed table of page faults, CPU time,
  and elapsed time per assembler phase, then the working set limit,
  intermediate code, symbol table space, source lines and object
  records, and macro definition counts.
- **Macro library statistics:** each library searched and how many
  macros it defined, and the number of GETs.
- **Summary:** `There were no errors, warnings or information messages.`
  (or the counts), then the command line as typed.

## The fidelity bar

A test compares govax's listing with real MACRO's line for line, after
masking:

- dates and times (both heading lines);
- the assembler's name and version, which govax writes as `govax MACRO
  V<build>` in the same field (as the object's language header already
  does);
- the source file specification (`DUA2:[000000]HELLO.MAR;1` against the
  test's own name);
- the CPU and elapsed times in the performance indicators — the labels
  and columns are still compared.

govax leaves out the run statistics it has no value for (Decision 2):
the page-fault column, the working set limit, and the other lines that
measure real MACRO's own memory (intermediate code bytes, symbol table
and macro pages). The comparison drops them from real MACRO's listing
too, through the allowed-differences table below, so the rest of each
section is still compared.

Everything else must match: pagination, headings, column positions, the
binary field, the symbol table, the psect synopsis, the counts of lines,
symbols, records, and macros, and the summary. A difference govax can't
or won't remove is listed in the test's own table of allowed differences,
each with its reason, and logged here (as the Phase 35 oracle's masks
are).

## Design

### Listing data, recorded during assembly

The assembler is one pass with fixups, so a statement's bytes aren't
final until the end (a forward reference is filled in later). The
listing is therefore built in two steps:

- **Recording (in `internal/asm`).** As each statement is assembled, the
  assembler appends a listing entry: the source text, the source frame
  (file, macro expansion, repeat block, library) and its line number, the
  psect and location, the byte range the statement stored, which fields
  in that range are relocated or linker-chosen, an assigned value, a
  `.PSECT` switch, the messages it produced, and the listing state in
  force (`.LIST`/`.NLIST` level, `.SHOW` options). Recording costs
  nothing when no listing was asked for.
- **Rendering**, after `finish()`: each entry's bytes are read back from
  the psect's final contents, so forward references show their real
  values, and the pages, symbol table, psect synopsis, and statistics
  are laid out. `Assembler.Listing(ListingOptions)` returns the lines;
  the options carry the heading's facts the assembler doesn't know (the
  date and time, the source file's name, revision date, and file
  number, the version, the command line, and the statistics).

The listing is written whether or not the assembly succeeded, as real
MACRO writes it, with each error in place; the object still isn't.

### Listing controls

`.LIST`/`.NLIST` (a level, and with arguments the same options as
`.SHOW`/`.NOSHOW`), `.SHOW`/`.NOSHOW` (`BINARY`/`MEB`, `CALLS`/`MC`,
`CONDITIONALS`/`CND`, `DEFINITIONS`/`MD`, `EXPANSIONS`/`ME`), `.PAGE`,
`.SBTTL`/`.SUBTITLE` (the second heading line, and the table of contents
if real MACRO writes one), and `.IDENT`'s place in the heading. MACRO's
`/SHOW=` qualifier sets the starting options. The manual's chapter 6
defines each; the probe shows what each looks like.

### Traceback and debugger records

TBT and DBG records hold DST records (debug symbol table records)
written as TIR commands: the record's length and type, stored
immediately, with a psect-relative address stored by
`STA_PB`/`STA_PL` + `STO_PIDR`. Real MACRO's traceback, read from
`hello.anl`, is a module-begin record, a routine-begin record for each
`.ENTRY` (its address and name), a PSECT record for each psect (address,
name, size), and a module-end record. A DST builder in `internal/obj`
(encode and decode DST records inside a TBT or DBG record) keeps the
assembler and LINK from each knowing the byte layout, and lets
`obj.Dump` show them decoded.

The DST record types are govax's own (`obj.DSTType`), worked out from
real MACRO's objects (Decision 6): neither the linker nor the debugger
manuals give their layouts, and VMS's definition files are outside the
clean room. (The plan had them going into `vmsdef.Symbols` through
`gen`.)

`/DEBUG` (and `.ENABLE DEBUG`) adds DBG records: by the manual, symbol
records for the module's labels, which the probe's `/DEBUG` objects
show exactly.

### LINK's debug symbol table

With traceback, real LINK gathers the modules' TBT records into the
image's DST, after the image sections, and points the image header's
symbol-table descriptor (IHS) at it. govax's LINK does the same, so
`withoutDST` goes away, and real VMS gives a symbolic traceback for a
govax-linked image. `/NOTRACEBACK` leaves the DST out, as it does now.

## Method: the fixtures, then the probe

1. The 30 real listings and 21 real objects already in `testdata/` are
   enough to build the source pages, the symbol table, the psect
   synopsis, and the traceback records for the common cases.
2. A probe (subtask 1) assembles, on VMS, sources written for what the
   fixtures don't cover: the listing directives, errors, the cross
   reference, `/DEBUG`, and runtime traceback output. Its results are the

**Clean room.** A real listing that shows a system macro's expansion
holds STARLET.MLB's text (Phase 32). The probe's sources never expand a
system macro with `.SHOW EXPANSIONS` (they use their own macros for every
expansion case, and any system macro call stays under `.NOSHOW ME,MEB`).
A probe listing that could show a system macro's text has its name put
in `.claude/hooks/cleanroom.sh`'s unaudited list until the author has
audited it, as Phase 28's three were. Subtask 1's sources call no system
macros at all, so none of its listings needs to be there.

## Decisions

The author decided each of these on 2026-10-02.

1. **The assembler's name in the heading.** `govax MACRO V<build>` where
   real MACRO writes `VAX MACRO V5.4-3`, as the object's language header
   already names govax; masked by the comparison.
2. **The run statistics.** Every section stays, with govax's own
   figures: real counts (source lines, object records, symbols, macros,
   library GETs) and measured CPU and elapsed times. Items govax has no
   value for are left out rather than shown as 0: the page-fault
   column, the working set limit, and the lines about real MACRO's own
   memory (intermediate code, symbol table and macro pages).
3. **Cross reference** (subtask 9). In scope.
4. **LINK/DEBUG.** Out of scope: an image linked `/DEBUG` starts in the
   debugger, which govax doesn't have. This phase's LINK writes the DST
   for traceback links only; `/DEBUG` objects still link, with their DBG
   records skipped. The probe still captures a `LINK/DEBUG` image for
   later.
5. **Listings for the console's `ASM` command** (the eVAX dialect). Out
   of scope: `ASM` doesn't make listings.
6. **DST records in strict clean room** (2026-10-04). The DST layouts
   come only from the manuals and real VMS output (the probe's objects,
   images, and logs), never from VMS's source or definition files. If
   that hits a dead end, DST support is deferred. There's no requirement
   to hand govax's objects or images back to VMS with full DST support.
   The future use is govax's own: traceback and debugger data for the
   console's SHOW CALLS and DISASM.

### 2026-10-02 — Subtask 2: listing entries

- **`internal/asm/listing.go`** records a `listLine` for every source
  line once `SetListing(true)` is called. That includes blank and
  comment lines, collected definition lines, lines a conditional
  leaves out, and continuation lines, at every level of the source
  stack. Macro library definitions are the exception: real MACRO never
  lists them.
- Each line records:
  - its frame (kind, depth, line number) and its text (an expansion's
    text has its arguments substituted);
  - where it started and where it left the location counter;
  - its statement number and directive, instruction, or macro name;
  - an assignment's value;
  - the fields it stored, each with its operand group;
  - its own errors, warnings, and `.PRINT` messages.
- Fields are recorded where bytes are stored: `advanceData`, plus the
  `.ASCID`, `.ASCIC`, and `.ENTRY` paths that store directly.
- `listFields` works out each field's final bytes after assembly. It
  uses the per-byte owner history (`byteStoredBy`), so a forward
  reference shows its final value and a field a later statement stored
  over shows what this statement stored. The marks come from the
  relocations the statement left:
  - a relocation is one field holding the linker's addend, marked `'`;
  - a G^ operand is a `G` mode byte plus the longword;
  - a constant stored through the linker's stack is marked `'` too.
- **`TestListingLines`** compares every program line of 27 real listings
  (the 12 ladder fixtures, 7 of the Phase 28 macro fixtures, and 8 of the
  probe's default-option listings) with the recorded lines. Each line's
  location, `.PSECT` location, assignment value, and binary field (with
  blanks taken out) must match. All match.
  - `fabalign` is left out: its comments were rewritten after the VAX

  it lists symbols and macros. While the assembly runs, the assembler
  records each definition and reference at the program line it's on.
  The listing then adds a page for each kind after the psect synopsis.
  The "Cross-reference output" phase is timed now. `.CROSS` and
  `.NOCROSS` are no longer ignored (`pseudoCross`), and the unused
  `ignoreRest` is gone.
- **What the probe's `xref.lis`, `xrefall.lis`, and `symxref.lis`
  showed:**
  - Each section starts a page labelled `Cross reference`, with a
    boxed title. The order is symbols, macros, opcodes, directives,
    registers. The performance indicators follow the last section on
    its page.
  - **Symbols.** The name (15 columns), `=` for a direct assignment, the
    8-digit value, then `-R` (relocatable) or `-XR` (external, value 0).
    Then the line that defined it and the lines that referred to it,
    each in 16 columns: a 2-column mark, the line number in 7, `(1)`, 4
    blanks. `G` and `W` aren't shown.
    - Every symbol is listed but local labels. That includes the ones
      the symbol table leaves out under `.ENABLE SUPPRESSION`.
    - A symbol defined in a macro expansion is defined at the calling
      line.
    - `.EXTERNAL`, `.WEAK` (and so `.GLOBAL`) refer to the symbols they
      name. `.END`'s transfer address isn't a reference.
  - **The `#-` mark** is on an instruction's register operands (any
    mode: `R0`, `(R2)+`), and on a symbol in a literal operand (`#COUNT`).
    A symbol used as an address (`MOVAL TABLE, R2`, `G^`) has no mark, nor
    has a register in a mask (`^M<R2>`). What the two characters mean
    separately isn't known; govax writes them together.
  - **Reference order** is the order of the line numbers' text: line 38
    comes before line 8 (`LIB$PUT_OUTPUT`).
  - **`.NOCROSS`** with no symbols leaves out everything from the next
    line to the next `.CROSS`: definitions (`HIDDEN` has none), symbol
    references, and directives (`.LONG` on line 22). The `.CROSS` that
    ends it isn't listed either; cross-referencing was off when its line
    began. `.NOCROSS COUNT` leaves out only `COUNT`, until `.CROSS
    COUNT`.
  - **Macros.** The name (18), the size (11), the definition and the
    calls, each in 17 columns (a 3-column blank mark).
  - **Opcodes.** The name as written, the 4-digit opcode, the lines, 14
    columns each. **Directives:** the name as written, the lines. `.ENDM`
    is listed though the definition collector takes it, not the
    directive table.
  - **Registers.** The name, the number of lines that referred to it
    (right-justified to column 19), and the lines, marked as above.
- **The MACRO command.**
  - `/[NO]CROSS_REFERENCE[=(option,...)]` (DCL id 1307, with an empty
    default as `/LIST` has, so it can be given bare). An unknown keyword
    fails with `BADKEYWORD`.
  - `govax macro --cross-reference` and `--cross-reference-kinds`.
  - HELP MACRO documents the qualifier and `.CROSS`/`.NOCROSS`.
- **Tests.**
  - `TestFixtureListings` now compares `xref` whole (with
    `/CROSS_REFERENCE`). It adds `xrefall` (`=ALL`) and `symxref`
    (`symtab.mar`, `/NOOBJECT`, so a record count of 0). All three
    match, with no allowed differences.
  - `xref_test.go` covers the choices below.
  - `TestDispatch_macroCrossReference` covers the DCL path, and
    `TestMacroCommand` the new `govax macro` options.
- **Clean room.** Before the author put the VMS source archive
  off-limits (partway through this subtask), part of its
  cross-reference facility's listing (CRF) had been read. Nothing here
  rests on it alone. Reference order is shown by `xref.lis` itself. The other rules
  that listing covered (wrapping, long names, a line named twice) are
  govax's own choices below.
- **govax's own choices**, which no real listing shows. The author said
  (2026-10-04) that format fidelity here matters less than having the
  same information, so these aren't probed further. They can be
  revisited if users find a difference.
  - **Wrapping.** An entry's references fill each line to 132 columns:
    5 for a symbol, 5 for a macro, 7 for an opcode, 8 for a directive,
    6 for a register. Further lines are indented to the first
    reference's column. Pages break as source pages do, with no
    repeated column headings.
  - A symbol name longer than 15 characters widens the name column to
    31, as the symbol table's does.
  - A line that names a symbol or register twice is one reference, with
    its first mark.
  - Names sort as text: `R10` before `R2`, and lines `10`, `100`, `9`.
  - A section with no entries is left out.
  - A macro's size is the 512-byte pages its body's text fills. Both
    real macros, one short line and four, show 1.
  - A library macro is listed at its calls, with no definition line.
    Nothing a library's definition does is recorded. *(Superseded
    2026-10-04, [PHASE-36.md](PHASE-36.md): real MACRO's listing of
    `forth.mar` defines a library macro at the line that loaded it.)*
  - A two-byte opcode's value is its bytes as a word, prefix low
    (`CVTDH` is `32FD`), as the binary field shows it.
  - `.NOCROSS` with no symbols also leaves out opcodes, macros, and
    registers. The real listings show it only for symbols and
    directives.
  - A `.CROSS SYM` while everything is off takes effect when everything
    is turned on again (the manual's note 2).
  - `.IF DF` and `.IF NDF` aren't references. A symbol in a
    displacement (`4(R2)`) or a branch target has no mark. The index
    register of an indexed operand is marked as an operand.

### 2026-10-04 — Subtask 10: DST records

- **Decision 6.** The author asked for strict clean room here. DST
  layouts come from the manuals and real VMS output only. Govax names
  the types itself, and nothing goes into `vmsdef` through `gen`.
- **What the sources give.**
  - The linker manuals (VMS 5.0, 7.7 and 7.8, and the 2.0 and 7.3
    editions) say how LINK treats DBG and TBT records: as TIR commands
    whose bytes go into the DST, not the image.
  - Neither they nor the V2.0 debugger reference give any DST record's
    layout. The probe's `ANALYZE/OBJECT` output shows only the TIR
    commands.
  - So the layouts come from the bytes of the 53 real objects in
    `testdata/mar` (the fixtures' and the probe's). Each DST record is a
    length byte (the bytes after it), a type byte, and its fields. An
    address is stacked (`STA_PL` or `STA_PB`) and stored (`STO_PIDR`).
- **Real MACRO's traceback** is four kinds of record (`obj.DSTType`):
  - **psect** (`B8`): a byte (0), the psect's base (`STA_PB`, even at
    offset 0), the counted name, and the size (a longword). One for each
    psect but the absolute one.
  - **module begin** (`BC`): five zero bytes and the counted name.
  - **module end** (`BD`): no fields.
  - **routine begin** (`BE`): a byte (0), the entry address (`STA_PL`,
    whatever the offset), and the counted name. One for each `.ENTRY`.
    There's no routine end record.

  What the zero bytes mean isn't known; every real object has 0 there.
- **The stream.** A DST record can start in one TBT record and end in
  the next, and a STORE IMMEDIATE runs across record boundaries (the
  end of one routine begin and the start of the next). So a module's TBT
  records are one stream, and its DBG records another.
- **`internal/obj/dst.go`**:
  - `DecodeDST` splits a stream into `DSTRecord`s. Each holds its type,
    its fields (zeros where the linker stores an address), and each
    address's own TIR commands, so a record re-encodes exactly. It also
    returns the TBT or DBG record each DST record ends in.
  - `EncodeDST` writes the commands back. Bytes go into STORE
    IMMEDIATEs of up to `MaxImmediate`, flushed only before an address,
    as real MACRO's are.
  - `DSTModuleBeginRecord`, `DSTModuleEndRecord`,
    `DSTRoutineBeginRecord`, and `DSTPsectRecord` build the four
    traceback records, for subtask 11.
  - `FormatDST` describes a record. `obj.Dump` lists the DST records
    after the TBT or DBG record each ends in, or the stream's error.
- **Tests.**
  - `TestDSTRealObjects` decodes the TBT and DBG streams of all 53 real
    objects (40 have traceback) and encodes them back. The commands match
    with adjacent STORE IMMEDIATEs joined; how they're split into records
    is the Builder's job, checked in subtask 11.
  - Every traceback record is one of the four kinds, and its constructor
    builds it exactly.
  - Unit tests cover a record spanning two TBT records, an immediate
    longer than `MaxImmediate`, malformed streams, and `Dump`.
- **For subtask 12 (debugger records).** The probe's `/DEBUG` objects'
  DBG records decode as DST records too, with five more types.
  - `08` appears to be a symbol's value: a flag byte (1 for an address,
    0 for a constant), then the value, then the name.
  - `0E` holds a name, a value, and nested bytes.
  - `BB` is like a routine begin, for a JSB label (`HELPER`).
  - `9B` holds the source file's specification and dates.
  - `B9` looks like a compact line-number table.

  `9B` and `B9` are the hard ones. Following Decision 6, if their bytes
  can't be worked out from the probe's objects, they're the part to
  defer.
